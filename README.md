# Оркестратор процессов оценки рисков

Командный учебный MVP для турнира по продуктовому программированию. Система моделирует запуск пяти процессов оценки рисков и предотвращает одновременную работу задач с общими эксклюзивными источниками данных.

**Важно:** это симулятор с виртуальным временем, а не подключённая к банковской инфраструктуре система. Данные о запусках синтетические.

## Что умеет ядро

- Принимает ручные и регламентные заявки с расчётной датой.
- Отклоняет дубли одной пары «процесс + расчётная дата» среди активных и ожидающих задач.
- Ставит конфликтующие задачи в очередь, а независимые запускает параллельно.
- Атомарно резервирует нужные ресурсы, избегая взаимных блокировок.
- Пересчитывает приоритет по типу запуска, длительности и времени ожидания.
- Освобождает ресурсы после завершения или ошибки, ведёт историю в памяти.
- Позволяет продвигать виртуальное время для демонстрации.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `src/models.py`, `src/orchestrator.py` | Модель задачи и ядро планирования |

## Установка

Нужен **Python 3.10 или новее**. Все команды ниже запускаются из корня репозитория:

```bash
python -m pip install -r requirements.txt
```

Основные зависимости: `pandas`, `numpy`, `matplotlib`, `streamlit`. Последняя понадобится после объединения PR с интерфейсом. Для ядра и `unittest` дополнительные библиотеки не нужны.

## Проверка и демонстрация

Автоматические тесты (в репозитории пока 7; новые тесты добавляются отдельно):

```bash
python -m unittest discover -s tests -v
```

Консольная симуляция:

```bash
python -m src.run_scenarios
```

Программа предложит выбрать сценарий от 1 до 5, выведет результаты и откроет диаграмму. Закройте окно графика для завершения процесса.

Интерфейс Streamlit (после добавления `ui/app.py` из [PR #4](https://github.com/rim-3483/product-programming/pull/4)):

```bash
streamlit run ui/app.py
```

Повторное создание исходных данных и аналитических графиков **перезаписывает** файлы в `data/` и `output/`:

```bash
python src/1_generate_data.py
python src/2_analysis.py
```

Подробности — в [инструкции по скриптам](src/README.md).

## Ограничения MVP

- Состояние очереди и история хранятся **в памяти** и теряются после перезапуска.
- Время моделируется вручную; тип `scheduled` сам по себе **не создаёт запуск по расписанию**.
- Текущий вариант Streamlit из PR #4 использует отдельный `Orchestrator` на сессию браузера: общая очередь между разными пользователями пока не реализована.
- `estimated_duration` используется симулятором как время до завершения; фактические расчёты рисков не выполняются.
- Графики и проценты в анализе получены из **синтетических**, а не реальных банковских журналов.
