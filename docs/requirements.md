# Требования к MVP оркестратора

## Проблема
Ручные и регламентные процессы оценки рисков могут одновременно обращаться к общим источникам данных и конфликтовать.

## Функциональные требования
1. Пользователь добавляет процесс с названием, датой данных и набором ресурсов.
2. Оркестратор сохраняет последовательность поступления задач.
3. Два процесса с общим эксклюзивным ресурсом не выполняются одновременно.
4. Независимые задачи могут выполняться параллельно.
5. После завершения или ошибки ресурсы освобождаются, и очередь перепроверяется.
6. Интерфейс показывает статусы: «В очереди», «Выполняется», «Завершено», «Ошибка».

## Ограничения первой версии
- Расчёты **не выполняются автоматически**; завершение имитирует пользователь.
- Данные и планировщик хранятся в памяти Python-процесса Streamlit.
- У каждого пользователя Streamlit отдельное состояние; настоящая синхронизация между N пользователями пока **не реализована**.
- Правила доступа к ресурсам считаются заданными вручную: строка ресурса включает нужную дату, например `portfolio:2026-11-20`.
- Реальные источники, расписание, приоритеты, ретраи, аудит и устойчивость после перезапуска — следующие этапы.

## План следующего этапа
Вынести оркестратор в общий backend-сервис, хранить очередь в SQLite или PostgreSQL, добавить воркеры, журнал событий и конкурентные нагрузочные тесты.
